# WCET and UPPAAL Container

This repository contains scripts to run Backsolving benchmarks to generate Figure 7 at different GPU clock speeds and generate WCET (Worst-Case Execution Time) analysis data.

> **The graphs generated by this script can vary depending on the machine used to run the benchmarks.**

## Prerequisites for WCET generation

### System Requirements
- NVIDIA GPU with adjustable clock speeds
- ARM64 architecture
- [Docker](https://docs.docker.com/engine/install/) with [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)
- `sudo` access for GPU clock speed control
- GitHub account with access to the private image

### Docker Image Access (ARM64 Architecture)

The benchmarks use a private container image hosted on GitHub Container Registry (GHCR), which only runs on ARM64 architecture.

> **If you don't have access to such a machine, we have provided the data we collected on our NVIDIA IGX already, which should allow you to run the UPPAAL models directly. If so, skip to the [UPPAAL Analysis](#uppaal-analysis) section.**

#### Step 1: Login to GHCR and Pull the Image
```bash
# Login to GHCR
echo "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" | docker login ghcr.io -u shubhaankar-sharma --password-stdin

# Pull the benchmarking image
docker pull ghcr.io/shubhaankar-sharma/backsolving-benchmarks:latest
```

## GPU Clock Speed Control

The experiments require running benchmarks at three different GPU clock speeds:

### Set GPU to 255 MHz
```bash
sudo nvidia-smi -lgc 255
```

### Set GPU to 1000 MHz  
```bash
sudo nvidia-smi -lgc 1000
```

### Reset GPU to Default Clock Speed
```bash
sudo nvidia-smi -rgc
```

**Note**: GPU clock speed changes require sudo privileges and may require a system reboot if the GPU becomes unresponsive.

## Running the Experiments

**IMPORTANT**: GPU clock speed changes must be done manually on the HOST, but benchmarks must be run INSIDE the container for proper access to the build environment.

### Complete Workflow (All Three Speeds)

#### Step 1: Run 255 MHz Experiment
```bash
# Set GPU speed manually (ON HOST)
sudo nvidia-smi -lgc 255

# Verify the speed was set (ON HOST)
nvidia-smi

# Launch the container (ON HOST)
docker run --runtime=nvidia --gpus all --cap-add CAP_SYS_PTRACE --ipc=host --ulimit memlock=-1 --ulimit stack=67108864 --rm -it \
  -v "$(pwd)/application_latencies_255:/workspace/application_latencies_255" \
  -v "$(pwd)/run_all_inside_container.sh:/workspace/run_all_inside_container.sh" \
  -v "$(pwd)/change_wcet.sh:/workspace/change_wcet.sh" \
  -v "$(pwd)/uppaal:/workspace/uppaal" \
  -w /workspace \
  ghcr.io/shubhaankar-sharma/backsolving-benchmarks:latest \
  bash

# Inside the container, run the benchmark
./run_all_inside_container.sh 255

# Exit the container (CTRL+D or type 'exit')
exit
```

## UPPAAL Analysis

This section provides step-by-step instructions for running UPPAAL-based WCET analysis to produce the final latency summary graph (UPPAAL.pdf) using our prebuilt Docker container with UPPAAL 4.1.26 Academic Edition.

### System Requirements

- **Memory**: 120+ GB of RAM recommended for analysis
- **Architecture**: Works on both ARM64 and x86_64
- **Docker**: Docker installed with sufficient memory allocation

**Note**: If you have less than 120GB of RAM, you can modify the memory settings in `run_uppaal.sh` by editing the `--memory=128g --memory-swap=256g` parameters, but the analysis may run out of memory during execution.

### Step 1: Login to GitHub Container Registry

```bash
# Login to GHCR (same as before)
echo "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" | docker login ghcr.io -u shubhaankar-sharma --password-stdin
```

### Step 2: Pull the UPPAAL Analysis Image

```bash
# Pull the UPPAAL analysis image
docker pull ghcr.io/shubhaankar-sharma/backsolving-uppaal:latest
```

### Step 3: Run UPPAAL Analysis

The analysis is fully automated using the `run_uppaal.sh` script, which:
1. Runs UPPAAL verification for each configuration (255 MHz, 1000 MHz, default) separately to optimize memory usage
2. Combines the results from all configurations
3. Generates the final comparison plots (UPPAAL.png and UPPAAL.pdf)

```bash
# Run the complete UPPAAL analysis
./run_uppaal.sh
```

The script will:
- Start the UPPAAL container with appropriate memory settings
- Process each configuration separately to reduce peak memory usage
- Combine results and generate the final comparison graphs
- Output results to the `./results/` directory

### Output Files

After completion, you'll find:
- `./results/uppaal_results.csv` - Combined CSV data from all configurations
- `./results/UPPAAL.png` - Comparison plot in PNG format
- `./results/UPPAAL.pdf` - Comparison plot in PDF format
- `./results/255/`, `./results/1000/`, `./results/default/` - Individual configuration results

### Memory Configuration

If you need to adjust memory settings due to system limitations:

1. Edit `run_uppaal.sh`
2. Modify line 33: `--memory=128g --memory-swap=256g`
3. Reduce values based on your available RAM (e.g., `--memory=64g --memory-swap=128g`)

**Warning**: Reducing memory may cause the analysis to fail with out-of-memory errors for larger models.

### Technical Details

The analysis uses UPPAAL 4.1.26 Academic Edition, which doesn't require a separate license acquisition. The container includes:
- Pre-configured UPPAAL verifyta binary
- Python analysis pipeline (`graph_pipeline.py`)
- All necessary dependencies for WCET analysis

**Note on Synthetic WCET Values**: Two applications (ORSI Multi AI and AR, and MultiAI Ultrasound) were incompatible with our existing Holoscan container environment. To address this limitation, we employed synthetic WCET values derived from analogous graph patterns and operators (e.g. preprocessor -> preprocessor, multiai_inference -> multiai_inference, etc.) and their corresponding clock speeds, which were then mapped to the respective .xml configuration files.

The graphs and analysis presented incorporate these synthetic WCET values where direct measurements were not obtainable due to the technical constraints described above.

## Scripts Description

- `run_uppaal.sh` - **Main script** - Run complete UPPAAL WCET analysis (automated)
- `run_wcet_analysis.sh` - Generate WCET analysis from collected benchmark data (for reference)
- `change_wcet.sh` - Processes benchmark results and generates WCET data for UPPAAL
- `uppaal/` - Directory containing WCET analysis scripts and UPPAAL model files

**Note**: `run_all_inside_container.sh` is for benchmarking workflows, not UPPAAL analysis.

## Troubleshooting

### Docker Permission Issues
If you encounter permission errors with output files:
```bash
# Run with user ID mapping
docker run --user $(id -u):$(id -g) ...
```

### GPU Clock Speed Issues
- If GPU becomes unresponsive after clock changes, reboot the system
- Check current GPU status: `nvidia-smi`
- Verify clock speed changes took effect before running benchmarks

### GitHub Container Registry Access Issues
- Ensure your GitHub Personal Access Token (PAT) has `read:packages` scope
- Verify you have access to the `ghcr.io/shubhaankar-sharma/backsolving-benchmarks` package
- For organization repositories, ensure SSO is authorized on your PAT

### Missing Dependencies
If the `dot` command is not found during graph generation:
```bash
# Install Graphviz
sudo apt-get update && sudo apt-get install -y graphviz
```
